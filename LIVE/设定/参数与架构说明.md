# LUMA Live 参数与架构说明

## 一、角色分工

| 角色 | 对应代码 | 职责 |
|------|---------|------|
| **LUMA官方运营组** | `syncLiveSessions` / `lumaOpsPoll`（定时器轮询） | 定期读取参数，通过概率模拟 AI 决策，决定是否通知房管开播/下播 |
| **房管** | `lumaOpsGateway`（含 tool handlers） | 审核开播/下播申请，防多开、防分身、维护模式拦截，管理直播间开关 |
| **AI（概率模拟）** | 运营组内的掷骰子逻辑 | 基于基础意愿 + 比例式增长做决策 |

**关键原则**：运营组只负责"问"和"递参数"，不直接开关直播间；AI（概率）做决定；房管管权限和审核。

---

## 二、参数体系

### 2.1 开播/下播核心参数

| 参数 | 范围 | 默认 | 说明 |
|------|------|------|------|
| `maxLiveDuration` 直播时长上限 | 10-300分钟 | 120 | 达到则跳出安全区，必然下播。 |
| `maxRestDuration` 休息时长上限 | 10-720分钟 | 360 | 达到则跳出安全区，必然开播。 |
| `minRestDuration` 强制休息期 | 5-30分钟 | 10 | 下播后绝对不能开播，房管直接驳回。 |

### 2.1.1 AI 聊天驱动的意愿值系统

开播/下播的**基础意愿不再由玩家手动设置**，而是由角色在聊天中根据与用户的互动自主决定。

**实现机制**：
- manifest 注册了两个聊天指令 `[开播意愿:数值]` 和 `[下播意愿:数值]`（0-50）
- 角色每次聊天回复时输出这两个值，宿主的状态值解析器自动提取并存为角色状态值
- 官方运营组轮询前调用 `readRelations()` 刷新最新意愿值
- 未聊天过的角色使用默认值（开播25% / 下播10%）
- 开播成功后：`开播意愿` 清零（writeState），开始累积下播意愿
- 下播成功后：`下播意愿` 清零（writeState），开始累积开播意愿

### 2.2 运营组参数

| 参数 | 范围 | 默认 | 说明 |
|------|------|------|------|
| `opsPollInterval` 后台轮询间隔 | 3-10分钟 | 3 | 官方运营组多久轮询一次。修改后需重启轮询（重播开屏动画）。 |

## 三、决策公式

### 3.1 安全区判定

| 角色状态 | 安全区条件 | 跳出安全区 |
|---------|-----------|-----------|
| 直播中 | 已播时长 < 直播时长上限 | 已播 >= 上限 → 下播意愿 = 100% |
| 休息中 | 已休息时长 < 休息时长上限 | 已休息 >= 上限 → 开播意愿 = 100% |

**跳出安全区 = 必然决策，不掷骰子。**

### 3.2 安全区内：比例式增长

```
比例增长 = (已持续时长 / 上限时长) × 50%    ← 线性增长，最高50%
有效意愿 = 基础意愿 + 比例增长
```

### 3.3 掷骰子

```
Math.random() × 100 < 有效意愿  →  通过，AI 决定执行
```

### 3.4 举例

**开播**（角色开播意愿 25%，休息上限 360 分钟）：

| 已休息 | 安全区? | 比例增长 | 有效意愿 | 结果 |
|--------|--------|---------|---------|------|
| 0 分钟 | ✅ | 0% | 25% | 1/4 概率开播 |
| 180 分钟 | ✅ | 25% | 50% | 一半概率 |
| 300 分钟 | ✅ | 41.7% | 66.7% | 大概率 |
| 360 分钟 | ❌ | — | 100% | 必然开播 |

**下播**（角色下播意愿 10%，直播上限 120 分钟）：

| 已播 | 安全区? | 比例增长 | 有效意愿 | 结果 |
|------|--------|---------|---------|------|
| 0 分钟 | ✅ | 0% | 10% | 极少下播 |
| 60 分钟 | ✅ | 25% | 35% | 1/3 概率 |
| 100 分钟 | ✅ | 41.7% | 51.7% | 一半概率 |
| 120 分钟 | ❌ | — | 100% | 必然下播 |

## 四、开播全流程

```
官方运营组轮询（每 opsPollInterval 分钟）
│
└─ 对【休息中】的角色：
   │
   ├─ ① 强制休息期：已休息 < minRestDuration？→ 是则跳过
   │
   ├─ ② 读取角色开播意愿（AI聊天驱动，默认25%）
   │
   ├─ ③ 安全区判定：已休息 >= 休息时长上限？
   │     ├─ 是 → 开播意愿 = 100% → 直接决定开播
   │     └─ 否 → 有效意愿 = 角色开播意愿 + (已休息/上限)×50%
   │
   ├─ ④ 掷骰子：通过？
   │     ├─ 否 → AI 决定不播，跳过
   │     └─ 是 → AI 决定开播！
   │
   └─ ⑤ 通知房管（lumaOpsGateway.requestStartLive）审核：
         ├─ 已在直播中？→ 驳回
         ├─ 强制休息期？→ 驳回
         └─ 通过 → 创建直播间，投射广场，记录开播时间，开播意愿清零
```

## 五、下播全流程

```
官方运营组轮询（同一轮）
│
└─ 对【直播中】的角色：
   │
   ├─ ① 安全区判定：已播 >= 直播时长上限？
   │     ├─ 是 → 下播意愿 = 100% → 直接决定下播
   │     └─ 否 → 有效意愿 = 角色下播意愿 + (已播/上限)×50%
   │
   ├─ ② 掷骰子：通过？
   │     ├─ 否 → AI 决定继续播，跳过
   │     └─ 是 → AI 决定下播！
   │
   └─ ③ 通知房管（lumaOpsGateway.requestStopLive）审核：
         ├─ 未在直播？→ 驳回
         └─ 通过 → 关闭直播间，从广场移除，记录下播时间，进入休息期，下播意愿清零
```

---

## 六、房管审核规则

### 开播审核（requestStartLive）
- 角色在强制休息期内 → 驳回（返回剩余休息时间）
- 角色已在直播中 → 驳回（返回当前房间号）
- 通过 → 创建会话，分配房间号，设置 startTime/endTime，writeState 清零开播意愿

### 下播审核（requestStopLive）
- 角色当前未在直播 → 驳回
- 通过 → 删除会话，记录 lastEndTime，从广场移除
